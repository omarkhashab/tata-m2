# Late-start test

Generated by `python -m kestrel_m2.stream.late_start_test`. The producer replayed the whole feed and exited **25.4 s** after the start; only then was the consumer started.

Producer: 9,574 messages + 3 EOS records at a fixed 400 msg/s (achieved 399.0 msg/s), per partition {'0': 2999, '1': 3520, '2': 3055}; `stated_goal` fingerprinted on 4,215 records, 68 non-object elements forwarded as-is.

| run | group | auto_offset_reset | first offset read per partition | messages read | accepted | rejected | committed offsets at exit |
|---|---|---|---|---:|---:|---:|---|
| 1 late start | `kestrel-tata` | `earliest` | {'0': 0, '1': 0, '2': 0} | 9,577 | 8,827 | 747 | {'0': 3000, '1': 3521, '2': 3056} |
| 2 probe, new group | `kestrel-tata-latest-probe-1795352467` | `latest` | - | 0 | 0 | 0 | {'0': None, '1': None, '2': None} |
| 3 same group again | `kestrel-tata` | `earliest` | - | 0 | 0 | 0 | {'0': 3000, '1': 3521, '2': 3056} |

## What `auto_offset_reset` did

* **Run 1.** The group `kestrel-tata` had never committed an offset, so on its first poll Kafka applied `auto_offset_reset='earliest'`. The first offset read is 0 on every partition, so the consumer read the entire replay although it was started after the producer had finished. Messages are retained on the broker, and a consumer does not have to be running when they are produced.
* **Run 2.** A new group with `auto_offset_reset='latest'` starts at the end of each partition. It read nothing because nothing was produced after it joined. With `latest`, the late-start test would have silently lost the whole feed.
* **Run 3.** The same group again reads nothing: its offsets were committed after each successful write (Kafka topics flushed, then the PostgreSQL transaction committed), and committed offsets take precedence. `auto_offset_reset` only applies when a group has no valid committed offset.
